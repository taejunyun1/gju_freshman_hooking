# 로그인 없는 진로 탐색과 선택형 이메일 상담

## 확정한 흐름

- 공식 홈페이지에서 ‘나의 사진·영상 진로 찾기’ 버튼으로 별도 공개 페이지 `/explore`에 진입한다.
- 계정 없이 기존 네 단계 설문과 추천 로직을 사용한다. 기존 학생/관리자 흐름은 유지한다.
- 선택과 결과는 현재 탭의 sessionStorage에만 저장한다. 새로고침은 복원하고 ‘처음부터’는 지운다. 브라우저 복원 기능에 따라 탭 데이터가 복원될 수 있음을 고려한다.
- 추천 계산은 서버에서 하지만 공개 응답, 학생 계정, 결과 이력, 이벤트를 DB에 기록하지 않는다. 공개 학과 자료만 캐시해 재사용한다.
- 상담은 별도 선택 사항이다. 이름·휴대전화·선택 질문·동의를 입력하면 선택 관심사/추천 요약과 함께 photographygju@gmail.com으로 전송한다.
- 상담 개인정보는 브라우저 저장소나 앱 DB에 저장하지 않는다. 수신 메일함에는 남으므로 동의 안내에 수신자/목적/항목을 명시한다. 보관 기간은 학과 정책 확인 전 임의 확정하지 않는다.
- 수신 주소는 서버와 Cloudflare binding에 고정한다. 공개 사용자가 임의 주소로 메일을 보낼 수 없다.
- JSON 크기 제한, 같은 출처 확인, 서버 입력 검증, Cloudflare 요청 제한, 중복 클릭 방지를 적용한다. 메일 실패는 접수 성공으로 표시하지 않는다.
- 새 유료 서비스/AI API/DB 테이블은 추가하지 않는다. Gmail 수신 확인을 완료한 뒤 실제 발송을 검증한다.

## 구현 순서와 검증

1. 기존 추천 계산을 쓰기 없는 공통 함수로 분리한다. 기존 완료 흐름 회귀 테스트를 통과시킨다.
2. 공개 선택지/결과 API, 이메일 상담 검증 및 전송 모듈을 만들고 실패/오입력/수신자 고정 테스트를 작성한다.
3. 기존 파란색·라운드 디자인과 선택 카드를 재사용해 공개 페이지와 상담 폼을 만든다. 새로고침/초기화/미동의/오류 표시를 확인한다.
4. Cloudflare 무료 verified-destination email 및 요청 제한 binding을 설정한다. 타입·테스트·빌드 후 배포한다.
5. 공식 홈페이지에 진입 CTA를 연결한다. 기존 홈페이지의 다른 수정은 보존한다. 수신 확인/실제 메일 QA가 남으면 완료와 분리해 보고한다.

## 구현 및 검증 기록

- 공개 자료 캐시 10분, 기존 추천 계산 함수 재사용, 개인정보/설문 결과 DB 쓰기 없음.
- 전체 테스트 116개 파일 / 1,391개 통과. 타입 검사 및 변경 파일 ESLint 통과.
- 실제 공개 학과 데이터로 네 단계 설문, 결과 생성, 새로고침 선택 복원, 휴대전화 자동 서식, 메일 미연결 오류 표시를 브라우저에서 검증했다.
- 공식 홈페이지의 메인 이미지 아래 및 네 분야 안내 아래에 동일한 공개 설문 링크를 추가한다. 홈페이지 빌드 성공. 기존 홈페이지 테스트의 교수 정렬/이미지 정책 실패는 이번 수정 대상이 아니다.
- Supabase가 INACTIVE였으므로 기존 프로젝트를 복원했다. 데이터/비밀번호/스키마는 변경하지 않았다.

## 마지막에 남겨 둔 이메일 활성화

사용자 요청에 따라 Gmail 수신 확인은 마지막 단계로 보류했다. Cloudflare Email Routing은 활성화했고 수신 확인 메일은 발송했으나, `COUNSELING_EMAIL` binding은 아직 배포 설정에 넣지 않았다. 따라서 현재 상담 전송은 접수 성공 대신 이메일 연결 준비 중 안내를 반환한다.

수신 확인 후 production과 staging에 다음 binding을 각각 추가하고, 실제 테스트 메일 한 건으로 도착 여부를 확인한다.

```json
"send_email": [{ "name": "COUNSELING_EMAIL", "destination_address": "photographygju@gmail.com" }]
```

고정 발신 주소는 `counseling@gjuphoto.com`이다. 학생/관리자 비밀번호나 DB migration은 이 활성화 작업과 관계없으며 변경하지 않는다.
