# PHOTO:NEXT 최소 사진 배치 디자인

## 목표

텍스트 중심인 학생 화면에 실제 학과 사진을 최소한으로 추가한다. 사진은 장식이나 결과의 주인공이 아니라, 광주대학교 사진영상미디어학과의 학생 활동과 제작 환경이 실제로 존재한다는 시각적 근거로 사용한다.

한 화면에서 사진이 교과·교수·진로보다 강하게 보이지 않도록 첫 화면에는 1장, 결과 화면에는 관심 분야에 맞는 시설 사진 2장만 노출한다. 슬라이더, 자동 재생, 사진 갤러리, 관리자용 이미지 CMS는 만들지 않는다.

## 확인된 원본

원본은 프로젝트 상위 `resource` 폴더의 WebP 8장이다.

- 학생 활동: `행사 촬영_1.webp`, `전시관람_1.webp`
- 제작 공간: `스튜디오A.webp`, `스튜디오B.webp`, `컴퓨터실.webp`, `프린트랩.webp`, `학과 암실.webp`
- 보조 공간: `학생도서관 및 휴게실.webp`

모든 사진은 1,024px 이상의 가로 해상도를 가지며 웹 배치에 충분하다. 이번 범위에는 학생 작품 단독 이미지가 없으므로 작품·포트폴리오 예시를 실제 작품처럼 표시하지 않는다.

## 배치

### 첫 화면

`행사 촬영_1.webp` 한 장을 소개 문구와 CTA 아래에 배치한다. 학생 활동의 분위기를 보여주는 사진이며, 텍스트 배경으로 사용하지 않는다.

- 데스크톱: 콘텐츠 폭 안의 가로형 프레임, 비율 약 `16 / 7`
- 모바일: 비율 `4 / 3`, 중앙 인물군을 유지하도록 `object-fit: cover`
- 캡션: `사진과 영상으로 현장을 경험하는 사진영상미디어학과`
- 사진은 CTA보다 뒤에 배치하여 시작 행동을 방해하지 않는다.

### 결과 화면

결과 상단에는 사진을 추가하지 않는다. 관심사·점수·교과·교수의 읽기 순서를 유지하고, `이 제작을 가능하게 하는 학과 기반` 영역의 첫 부분에 `실제 제작 공간` 사진 카드 2개를 표시한다.

관심 분야별 사진 매핑은 결과의 `rankedTracks[0]`만 사용한다.

| 관심 분야 | 사진 1 | 사진 2 | 설명 초점 |
|---|---|---|---|
| 다큐멘터리 사진 | 학과 암실 | 프린트랩 | 기록 이미지의 현상·편집·출력 |
| 예술사진 | 학과 암실 | 프린트랩 | 물성과 출력까지 이어지는 창작 |
| 광고사진 | 스튜디오A | 스튜디오B | 호리존·조명 기반 상업 촬영 |
| 영상과 기술(AI·편집·드론) | 컴퓨터실 | 스튜디오A | 촬영과 편집·후반작업의 연결 |

사진 카드는 기존 시설·기자재 데이터 카드보다 앞에 오지만, 높이를 제한하여 메인 콘텐츠가 되지 않게 한다. 카드마다 공간명과 한 문장 설명만 둔다. 수량·예약·기자재 정보는 기존 카드가 계속 담당한다.

`전시관람_1.webp`는 현재 프로젝트와 직접 연결되는 근거가 없으므로 결과 카드에 반복 사용하지 않는다. 추후 비교과 데이터와 실제 행사명이 확인되면 별도 범위에서 연결할 수 있다.

## 컴포넌트와 데이터 경계

- 정적 사진 정보는 새 공통 모듈에 `TrackKey`별 두 장으로 선언한다.
- 사진 파일은 빌드에 포함되는 공개 정적 경로 아래로 복사하고 영문 파일명을 사용한다.
- 첫 화면은 고정된 학생 활동 사진 한 장을 사용한다.
- 결과 화면은 `ResultTimeline`이 최우선 관심 분야를 사진 컴포넌트에 전달한다.
- 사진 컴포넌트는 경로, 공간명, 설명, 대체 텍스트만 렌더링한다.
- DB, Supabase, 결과 스냅샷, API 응답 형식은 변경하지 않는다.

예정 경로는 다음과 같다.

```text
public/images/department/
  field-activity.webp
  studio-a.webp
  studio-b.webp
  computer-lab.webp
  print-lab.webp
  darkroom.webp
```

## 시각 규칙

- 기존 블루 포토 노트의 흰 표면, 파란 테두리, 라운드 반경을 그대로 사용한다.
- 사진에 컬러 오버레이나 그라데이션을 얹지 않는다.
- 사진 위에 제목이나 본문을 겹치지 않는다.
- 공간명은 사진 아래의 작은 모노 라벨, 설명은 한 문장 본문으로 표시한다.
- 데스크톱은 2열, 모바일은 1열이다.
- 사진 자체의 강한 색은 허용하되 UI 포인트 색은 기존 파란색만 유지한다.
- 시그니처는 서로 다른 두 공간을 한 쌍의 `제작 근거 프레임`으로 보여주는 것이다.

## 성능과 접근성

- 첫 화면 사진은 초기 화면에서 보일 때만 일반 로딩하고 고정 크기를 선언해 레이아웃 이동을 막는다.
- 결과 화면 사진은 `loading="lazy"`와 `decoding="async"`를 사용한다.
- 원본 WebP를 유지하며, 구현 시 표시 크기에 비해 과한 원본은 품질을 해치지 않는 범위에서 리사이즈한다.
- 모든 사진에 맥락을 설명하는 한국어 `alt`를 제공한다.
- 장식용 배경 이미지로 처리하지 않으며 키보드 동작을 추가하지 않는다.
- 이미지 로딩 실패 시 공간명과 설명은 남고, 깨진 이미지 아이콘 대신 사진 영역만 숨긴다.

## 오류 처리

정적 이미지가 누락되더라도 진단·결과 조회·상담 기능은 정상 동작해야 한다. 사진 매핑이 없는 관심 분야가 생기면 사진 영역을 렌더링하지 않고 기존 학과 기반 카드만 표시한다. 이미지 오류는 서버나 DB 오류로 취급하지 않는다.

## 검증

- 네 관심 분야가 정확히 두 장의 지정 사진과 연결되는지 단위 테스트한다.
- 첫 화면에는 한 장, 결과 화면에는 최대 두 장만 렌더링되는지 컴포넌트 테스트한다.
- 이미지에 대체 텍스트, 고정 비율, 지연 로딩 속성이 있는지 확인한다.
- 320px 모바일과 데스크톱에서 크롭, 텍스트 줄바꿈, 가로 오버플로우를 시각 확인한다.
- 이미지 요청 실패 시 핵심 결과와 기존 시설·기자재 카드가 남는지 확인한다.
- 전체 테스트, 타입 검사, 린트, 프로덕션 빌드를 통과한다.

## 비목표

- 교수 프로필 사진 추가
- 학생 작품 갤러리 또는 프로젝트별 썸네일
- 사진 업로드·교체용 관리자 기능
- 캐러셀, 라이트박스, 자동 재생
- 사진을 이용한 점수·교수·교과 추천 로직 변경
