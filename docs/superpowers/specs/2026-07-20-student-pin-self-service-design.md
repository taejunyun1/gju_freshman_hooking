# 학생 PIN 자가 관리 및 관심사 기록 초기화 설계

## 목표

입시생은 별도의 개별 안내 없이 숫자 6자리 초기 PIN으로 로그인하고, 로그인 뒤에는 자신의 PIN을 바꿀 수 있다. PIN을 잊은 경우에는 기존 관심사 기록을 삭제한다는 점을 분명히 확인한 뒤 초기 PIN으로 되돌리고, 곧바로 새 관심사 설문을 시작한다.

이 서비스는 1년 1회 약 200명 규모의 관심사 탐색 서비스다. 따라서 복잡한 계정 복구나 문자 인증을 추가하지 않고, 기존 로그인 제한·세션·HMAC/bcrypt 검증을 유지한다.

## PIN 규칙

- 초기 PIN: `입학연도 뒤 2자리 + 휴대전화 끝 4자리`.
- 2026년 예시: `010-4225-9442`는 `269442`.
- 형식: 숫자 6자리만 허용한다.
- 학생이 바꾸는 PIN도 숫자 6자리다. 복잡도 규칙은 추가하지 않고, 새 PIN 확인 입력만 요구한다.
- 초기 PIN은 편의용 입장 PIN이며 휴대전화 번호와 독립된 강한 비밀번호가 아님을 로그인/재설정 화면에서 과장 없이 안내한다.
- 평문 PIN을 DB에 저장하지 않는다. Worker HMAC 사전처리와 PostgreSQL bcrypt 저장·검증 계약은 계속 사용한다.

## 학생 흐름

### PIN 변경

1. 로그인한 학생이 결과 이력 화면의 `내 PIN 관리`로 이동한다.
2. 현재 PIN, 새 숫자 6자리 PIN, 새 PIN 확인을 입력한다.
3. 서버는 현재 세션과 현재 PIN을 모두 검증한 뒤 PIN을 변경한다.
4. 모든 기존 학생 세션을 무효화하고, 현재 브라우저에는 새 세션을 발급한다.
5. 성공 화면은 `PIN이 변경되었습니다`와 다시 로그인할 필요가 없다는 안내만 표시한다.

### PIN 분실 후 재시작

1. 로그인 화면의 `PIN을 잊으셨나요?` 링크를 누른다.
2. 휴대전화 번호를 다시 입력한다.
3. 삭제 대상과 보존 대상을 명확히 보여 준다.
   - 삭제: 설문 응답, 결과 스냅샷, 최근 결과 이력, 진로 제안 생성 기록·신고.
   - 보존: 이름, 연락처, 출신고교, 학년, 상담 신청.
4. `기존 관심사 기록을 삭제하고 다시 시작합니다` 확인란과 `삭제 후 초기 PIN으로 재설정` 버튼을 제공한다.
5. 서버는 현재 학년도 활성 학생만 찾고, 해당 학생의 관심사 기록을 삭제한다. 상담 신청은 보존되며 연결된 결과만 비운다.
6. PIN을 해당 학생의 초기 PIN으로 재설정하고, 새 세션을 발급해 `/assessment`로 이동한다.

## 서버·DB 경계

### 새 RPC

- `change_roster_student_pin_self_v1`
  - 인증된 `prospect_id`, 현재 PIN digest, 새 PIN digest를 받는다.
  - 현재 학년·활성 학생인지 확인하고 bcrypt로 현재 digest를 검증한다.
  - 새 bcrypt digest, 실패 횟수와 잠금 상태를 갱신하고 모든 이전 세션을 무효화한다.
- `reset_roster_student_pin_and_assessment_v1`
  - 전화번호 HMAC, 새 초기 PIN digest, 새 세션 hash, 만료 시각, IP HMAC을 받는다.
  - 현재 학년도 활성 학생만 잠근다.
  - 전화번호별·IP별 제한을 적용한다.
  - 해당 학생의 `assessments`를 삭제한다. FK cascade로 `assessment_responses`, `assessment_narrative_generations`, `career_narrative_reports`가 함께 삭제된다.
  - `counseling_requests.assessment_id`는 `on delete set null`이므로 상담 신청은 유지된다.
  - 관심사 관련 이벤트(`assessment_*`, `result_viewed`, `resource_opened`)만 제거한다. 로그인 실패·성공 등 운영 보안 이벤트는 유지한다.
  - PIN과 세션을 한 트랜잭션으로 재설정한다.

기존 학생의 숫자+영문 초기 비밀번호는 자동으로 해독하거나 일괄 변경하지 않는다. 새 로스터 생성·개별 PIN 재설정·분실 재시작부터 숫자 PIN을 사용한다. 필요할 경우 관리자가 기존 학생 명단을 다시 적용해 숫자 초기 PIN을 발급할 수 있다.

## 보안·오류 처리

- PIN 변경은 학생 세션의 CSRF 보호 대상에 포함한다.
- 분실 재시작은 로그인과 같은 일반 오류 메시지로 학생 존재 여부를 노출하지 않는다.
- 분실 재시작은 전용 전화번호/IP rate limit을 적용하며, 실패 5회 잠금과 기존 전역 로그인 제한을 보완한다.
- 삭제 확인 전에는 어떤 DB 변경도 수행하지 않는다.
- 재설정 성공 후에는 오래된 결과 URL과 세션이 더 이상 학생 데이터에 접근하지 못한다.
- 상담 신청을 보존했다는 사실은 재설정 완료 화면에 간단히 안내한다.

## 화면 설계

- 기존 PHOTO:NEXT의 파란색·둥근 패널·작은 모노 라벨을 유지한다.
- `내 PIN 관리`는 이력 화면의 하단 보조 영역에 두어 결과 탐색보다 앞에 나오지 않게 한다.
- 삭제 재시작 화면은 얇은 빨간 경고선과 한 개의 확인란만 사용한다. 불필요한 다단계 모달이나 강한 색상은 쓰지 않는다.
- 숫자 키패드가 열리도록 모든 PIN 입력에 `inputmode="numeric"`와 숫자 6자리 길이 제한을 사용한다.

## 검증

- 숫자 6자리 PIN만 로그인·로스터 자격증명·변경 요청에서 허용되는지 단위 테스트한다.
- PIN 변경 성공/현재 PIN 불일치/새 PIN 확인 불일치를 테스트한다.
- 분실 재시작이 관심사 데이터만 제거하고 상담 신청과 학생 로스터는 보존하는지 DB 테스트한다.
- 재설정 뒤 기존 세션과 기존 결과가 접근 거부되는지 통합 테스트한다.
- 로그인, 이력, PIN 관리, 재시작 화면의 주요 안내·확인 동작을 컴포넌트 테스트한다.
