# PHOTO:NEXT 블루 포토 노트 재디자인

## 목표

학생용과 관리자용 화면 전체를 하나의 블루 디자인 시스템으로 통합한다. 학생이 관심사에서 전공·교과·교수·진로로 이어지는 경로를 편안하게 읽도록 하고, 관리자는 같은 시각 언어 안에서 높은 정보 밀도를 다룬 수 있게 한다.

## 적용 범위

- 학생: 홈, 로그인, 진단, 결과, 히스토리, 상담
- 관리자: 로그인, 운영 홈, 학생, 연간 명단, 상담, 학과 자원, 교수진, 캠페인, 내보내기, AI 문장 신고
- 공통: 헤더, 로고, 버튼, 입력창, 카드, 태그, 테이블, 모달, 빈 상태, 오류 상태

## 시각 방향

이름은 **블루 포토 노트**다. 작업 노트와 포트폴리오의 여백을 가져오되, 카드와 조작 요소를 부드럽게 라운드 처리한다. 화면이 유치해 보이지 않도록 필 모양은 보조 태그에만 사용하고, 핵심 카드는 14–20px 반경을 사용한다.

시그니처는 ‘관심사에서 전공으로 이어지는 파란 경로’다. 진행 상태, 결과 타임라인, 관리자 현재 메뉴에 짧은 파란 선과 점을 사용한다. 순서나 연결 의미가 없는 곳에는 장식으로 반복하지 않는다.

## 디자인 토큰

### 색상

- `--color-primary: #2563EB`: 주요 버튼, 선택, 진행, 링크
- `--color-primary-strong: #14213D`: 기본 글자, 관리자 레일, 강한 대비
- `--color-primary-soft: #EAF1FF`: 선택 배경, 태그, 보조 카드
- `--color-canvas: #F5F8FF`: 전체 배경
- `--color-surface: #FFFFFF`: 카드와 입력 표면
- `--color-muted: #58677F`: 보조 글자
- `--color-error: #C53B3B`: 오류에만 사용하는 예외적 색상

기존 보라·청록·주황 포인트는 제거하고, 상태 차이는 블루의 명도, 테두리, 아이콘, 문구로 표현한다. 오류는 색상에만 의존하지 않고 텍스트와 아이콘을 함께 제공한다.

### 타이포그래피

- 페이지 제목과 핵심 카드: Wanted Sans Variable
- 본문과 폼: Pretendard Variable
- 상태, 데이터, 짧은 라벨: IBM Plex Mono
- 모든 `h1`의 시각 크기는 `clamp(1.75rem, 4vw, 2rem)` 이하로 제한한다.
- 기본 `h2`는 1.375–1.625rem, `h3`는 1.125–1.25rem로 유지한다.
- 제목에서 과한 자간 축소와 3줄 이상 줄바꿈을 피한다.

### 형태와 간격

- 카드: 18px, 작은 카드: 14px, 큰 패널·모달: 20px
- 버튼·입력창: 12–14px, 태그: 999px
- 표면 간 간격은 8px 기반 스케일로 정리한다.
- 기본 그림자는 사용하지 않고, 선택·호버·모달에만 얇은 블루 그림자를 적용한다.

## 정보 계층

학생 결과 화면의 순서는 아래와 같다.

1. 학생의 관심사와 전공 방향
2. 학습 경로와 교과과정
3. 총괄 교수와 연계 전문가
4. 진로 제안과 짧은 설명
5. 비교과·동아리·학생 활동
6. 기자재·시설을 학습 가능성의 지원 근거로 표시

기자재와 시설은 전면의 메인 콘텐츠로 올리지 않는다. 해당 경로를 실현할 수 있는 근거를 2–4개의 작은 지원 카드로 제공한다.

## 학생 화면

- 홈: 거대한 영웅 제목을 줄이고, 핵심 문장과 진단 시작 카드를 같은 시야에 둡다.
- 로그인: 하나의 작은 인증 카드로 정리하고 전화번호와 임시 비밀번호에 집중한다.
- 진단: 선택 카드를 라운드 표면으로 정리하고, 선택 상태는 블루 테두리와 연한 배경으로 표시한다.
- 결과: 전공·교과·교수·진로 카드를 짧은 파란 경로로 연결한다.
- 히스토리·상담: 읽기 순서를 우선하고 상태 칩과 행동 버튼만 강조한다.

## 관리자 화면

- 데스크톱의 좌측 레일은 딥 네이비로 유지하되 선택 메뉴만 메인 블루로 표시한다.
- 모바일 레일은 패널 형식으로 압축하고 필수 메뉴를 우선 표시한다.
- 테이블은 셀마다 카드화하지 않고, 하나의 큰 라운드 표면 안에 행 구분선을 둔다.
- 필터, 폼, 모달, 상태 배지를 공통 토큰으로 통일한다.
- 관리 작업의 정보 밀도는 유지하고 제목의 크기와 장식만 줄인다.

## 상호작용과 접근성

- 호버 효과는 2px 이내의 이동과 얇은 그림자로 제한한다.
- 키보드 포커스는 메인 블루 3px 외곽선으로 명확하게 보여준다.
- `prefers-reduced-motion` 환경에서 전환과 애니메이션을 제거한다.
- 320px 너비에서 가로 오버플로우 없이 핵심 작업을 완료할 수 있어야 한다.
- 색상만으로 상태를 구분하지 않고 문구, 아이콘, 테두리 중 하나 이상을 함께 사용한다.

## 구현 경계

전역 토큰과 공통 기본 스타일을 먼저 바꾸고, 학생 핵심 여정, 결과, 관리자 공통 레이아웃, 개별 관리 페이지 순으로 적용한다. 기존 기능, 데이터 계약, 인증 흐름, 카피의 의미는 변경하지 않는다.

## 검증

- 토큰과 제목 크기 상한을 단위 테스트로 검증한다.
- 학생 홈, 로그인, 진단, 결과와 관리자 로그인, 학생 목록, 명단 관리를 데스크톱·모바일에서 시각 확인한다.
- 키보드 포커스, 320px 오버플로우, 최소 터치 크기, 축소 모션을 점검한다.
- 기존 테스트, 타입 검사, 린트, 프로덕션 빌드를 통과한 후 배포한다.

## 비목표

- 기능, API, DB 스키마, 인증 방식은 바꾸지 않는다.
- 사진이나 새로운 대형 애니메이션을 새로 추가하지 않는다.
- 기자재·시설을 학생 결과의 메인 콘텐츠로 올리지 않는다.
