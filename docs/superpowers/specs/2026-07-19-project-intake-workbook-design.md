# 프로젝트 입력 엑셀 템플릿 설계

작성일: 2026-07-19
대상: 광주대학교 사진영상미디어학과 PHOTO:NEXT 연결 프로젝트 데이터

## 목표

최근·진행·예정 프로젝트를 한 행씩 입력하면 현재 `resources` 및 `resource_tags` 구조로 안전하게 변환할 수 있는 `.xlsx` 템플릿을 제공한다. 프로젝트 근거와 학생 관심사 태그를 함께 수집해 결과 화면의 연결 프로젝트 추천을 강화한다.

## 파일 구성

워크북은 세 시트로 구성한다.

1. `프로젝트_입력`: 실제 데이터를 입력하는 표
2. `작성_가이드`: 열별 작성 규칙과 진행상태의 DB 변환 규칙
3. `태그_목록`: 설문과 직접 연결되는 대표트랙 및 관심태그 목록

한 프로젝트는 `프로젝트_입력` 시트의 한 행으로 표현한다. 여러 태그와 교수명은 세미콜론(`;`)으로 구분한다.

## 프로젝트 입력 열

| 열 | 필수 | 규칙 | 저장·변환 대상 |
|---|---:|---|---|
| 프로젝트키 | 필수 | 영문 소문자·숫자·밑줄, 행 간 중복 금지 | `metadata.seedKey` |
| 구분 | 필수 | 프로젝트 또는 비교과 | `resources.type` |
| 프로젝트명 | 필수 | 1~200자 | `resources.title` |
| 진행상태 | 필수 | 완료·진행중·예정확정·반복운영·확인필요 | `status`, `visibility`, `evidenceStatus` |
| 시작일 | 선택 | 실제 시작일 `YYYY-MM-DD` | 기간 검증 보조값 |
| 종료일 | 선택 | 실제 종료일 `YYYY-MM-DD` | 기간 검증 보조값 |
| 기간표시 | 필수 | 화면용 자유문구, 최대 100자 | `metadata.periodLabel` |
| 핵심내용 | 필수 | 사실 중심 1~1000자 | `resources.summary`의 중심 문장 |
| 학생이 한 활동 | 필수 | 기획·촬영·편집 등 | `summary` 보강 |
| 주요 결과물 | 선택 | 전시·영상·사진집 등 | `summary` 보강 |
| 대표트랙 | 필수 | 4개 트랙 중 하나 | 기본 `resource_tags`, 가중치 3 |
| 보조트랙 | 선택 | 세미콜론 구분 | 보조 `resource_tags`, 가중치 2 |
| 관심태그 | 필수 | 태그 목록 시트 값, 세미콜론 구분 | 보조 `resource_tags`, 가중치 2 |
| 연계문구 | 선택 | 비어 있으면 시스템 생성 | `connection_template` |
| 참여기관·장소 | 선택 | 공개 가능한 공식 명칭만 입력 | `summary` 보강 |
| 관련교수 | 선택 | 공개 가능한 교수명, 세미콜론 구분 | 원본 근거 보존 및 향후 연결 확장 |
| 출처페이지명 | 필수 | 공식 게시물 제목 | `archive.sourcePageTitle` |
| 출처URL | 필수 | HTTPS 공식 출처 | `archive.sourceUrl` |
| 출처확인일 | 필수 | 출처 수정일 또는 검증일 `YYYY-MM-DD` | `source_date`, `archive.sourceLastEditedDate` |
| 검증메모 | 필수 | 일정·인원·현재 운영 여부의 확인 범위 | `archive.verificationNote` |
| 우선순위 | 선택 | 0~300, 기본 0 | `resources.priority` |

## 상태 변환

| 입력 상태 | DB 상태 | 근거 상태 | 공개 범위 |
|---|---|---|---|
| 완료 | `active` | `historical` | `public` |
| 진행중 | `active` | `snapshot` | `public` |
| 예정확정 | 해당 연도는 `active`, 다음 학년은 `next_year_confirmed` | `snapshot` | `public` |
| 반복운영 | `active` | `recurring` | `public` |
| 확인필요 | `draft` | `verify_required` | `admin_only` |

완료 프로젝트의 요약에는 과거 운영 사례임을 명시한다. 예정확정은 공식 일정 출처가 있을 때만 사용할 수 있다.

## 태그 규칙

대표트랙은 다음 네 값만 허용한다.

- `documentary`: 다큐멘터리 사진
- `art_photo`: 예술사진
- `commercial`: 광고사진
- `video`: 영상과 기술

관심태그는 현재 설문에서 생성되는 키를 우선 사용한다. `태그_목록` 시트에는 태그 키, 한국어 의미, 연결되는 설문 범주를 함께 제공한다. 대표트랙은 정확히 하나이고 모든 태그 키는 한 행 안에서 중복될 수 없다.

## 검증과 사용 흐름

템플릿에는 드롭다운, 날짜 형식, 필수 열 강조, 예시 행을 포함한다. 입력 완료 후 다음 순서로 처리한다.

1. 프로젝트키·필수값·날짜·URL·중복 태그 검증
2. 진행상태에 따른 DB 상태와 공개 범위 산출
3. 핵심내용과 활동·결과물·기간을 안전한 요약문으로 조합
4. `resources`와 `resource_tags` 형식으로 변환
5. 검수 전 미확인 행은 공개하지 않음

현재 결과 카드는 `source_date`를 ‘기준’ 날짜로 표시하고 `periodLabel`을 별도 노출하지 않는다. 따라서 초기 데이터에서는 핵심내용 첫 문장에도 실제 프로젝트 기간을 포함한다. 결과 화면의 연결 프로젝트는 관심 적합도, 우선순위, 출처확인일을 기준으로 정렬되고 최대 3개가 노출된다.

## 범위 제외

이 템플릿 제작에서는 DB 마이그레이션, 관리자 업로드 기능, 결과 카드 레이아웃 변경, 기존 프로젝트 데이터 수정은 하지 않는다. 템플릿을 채운 뒤 별도 승인 단계에서 데이터 검증과 반영을 진행한다.
