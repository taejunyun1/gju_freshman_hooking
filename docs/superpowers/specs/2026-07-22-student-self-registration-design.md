# 신규 학생 간단 등록 설계

## 목표

명단에 없는 신규 학생도 로그인 화면에서 간단 등록으로 설문을 바로 시작할 수 있게 한다. 기존 명단 로그인, 관리자 명단 관리, 연도별 입시 주기는 그대로 유지한다.

## 사용자 흐름

1. 로그인 화면에 `처음 참여하나요? 간단 등록 후 설문 시작` 링크를 둔다.
2. 신규 등록 화면은 이름, 휴대전화 번호, 출신고교, 학년을 받는다. 이는 기존 개별 학생 명단과 동일한 입력 항목이다.
3. 제출이 성공하면 현재 입시 주기에 신규 학생을 추가하고 학생 세션을 만든 뒤 `/assessment`로 이동한다.
4. 화면에는 PIN 번호를 표시하거나 API 응답으로 반환하지 않는다. `PIN은 자동 생성되며, 다음 로그인부터 사용합니다.`만 안내한다.
5. 이후 로그인 PIN은 기존 규칙을 유지한다. 현재 입시 주기가 2027년이면 `27 + 휴대전화 뒤 네 자리`다.

## 데이터와 보안

- 현재 입시 주기는 서버가 조회한다. 클라이언트가 연도나 주기 ID를 보낼 수 없다.
- 이름과 휴대전화는 기존 명단과 같은 HMAC·암호화 과정을 거쳐 저장한다. PIN은 Worker에서 HMAC 사전 처리 후 bcrypt로만 저장한다.
- 신규 등록은 현재 주기의 활성 학생만 생성한다. 출신고교와 학년의 허용값은 기존 명단 검증 규칙을 재사용한다.
- 이미 같은 휴대전화가 명단에 있으면 기존 레코드를 수정하거나 세션을 만들지 않는다. 화면에는 기존 로그인으로 이동하라는 안내를 보인다.
- 공개 엔드포인트에는 IP 및 휴대전화 기반 rate limit을 적용한다. 별도 외부 서비스나 CAPTCHA를 추가하지 않는다.
- 성공 응답에는 세션 만료 시각만 포함하며 PIN, 이름, 전화번호, 암호화 값 또는 내부 학생 ID를 반환하지 않는다.

## 구현 경계

- `student-self-registration` 서비스: 입력 검증, 현재 주기 확인, PII 보호, 초기 PIN 파생, 등록 RPC 호출, 세션 생성.
- `POST /api/student/register`: 요청 컨텍스트를 만들고 성공 시 기존 학생 세션 쿠키를 설정.
- 등록 화면: 숫자만 입력해도 휴대전화 하이픈을 자동 표시하고 성공 시 설문으로 이동.
- DB RPC: 관리자 권한을 요구하지 않는 제한된 self-registration 전용 삽입만 수행한다. 기존 관리자용 `add_roster_student_v1`은 변경하지 않는다.

## 오류 처리와 검증

- 잘못된 입력은 해당 필드를 수정하도록 안내한다.
- 중복 번호는 로그인 안내로 처리한다.
- DB 또는 세션 저장 실패는 등록 완료로 보이지 않게 하며, 잠시 후 다시 시도하라는 일반 오류를 표시한다.
- 단위·라우트·DB SQL 테스트로 신규 생성, 중복 방지, PIN 비노출, rate limit 및 기존 로그인 회귀를 검증한다.

## 범위 제외

- 기존 학생 정보의 자동 갱신 또는 덮어쓰기
- SMS 발송, 이메일 인증, CAPTCHA, 외부 인증 서비스
- 관리자 명단 가져오기·내보내기 흐름의 변경
