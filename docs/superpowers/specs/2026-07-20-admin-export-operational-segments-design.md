# PHOTO:NEXT 관리자 내보내기 운영 분류 설계

## 목적

관리자가 학생 이름을 기억하지 않아도 `설문·상담 진행 상태`와 `실제 담당 교수`를 기준으로 명단을 내보낸다. 기존의 세 개 XLSX 시트와 개인정보 보호 흐름은 유지한다.

## 확정된 분류

`내보내기 대상`은 하나만 선택하는 상호 배타적 분류다.

| 화면 표기 | 저장값 | 판정 기준 |
| --- | --- | --- |
| 전체 학생 | 값 없음 | 현재 필터 조건을 만족하는 활성 학생 |
| 상담 신청자 | `counseling_requested` | 기준 시점 이전의 상담 요청이 하나 이상 있음 |
| 설문 완료자 (상담 미신청) | `completed_without_counseling` | 완료 설문은 있으나 상담 요청이 없음 |
| 설문 미완료자 | `not_completed` | 완료 설문이 없음 |

상담 신청자는 완료 설문을 바탕으로 생성되므로, `설문 완료자`와 중복하지 않도록 상담 신청자를 우선 분류한다. 현재 데이터에는 저장 중인 설문과 이탈 설문을 별도로 남기지 않으므로, `설문 미완료`는 "완료 결과가 없는 학생"을 뜻한다.

## 담당 교수 기준

`담당 교수`는 추천 교수가 아니라 **학생의 가장 최근 상담 요청에 실제 배정된 교수**를 뜻한다. 선택지는 `전체 담당 교수`, `미배정`, 활성 교수진 목록이다. 교수 필터와 대상 분류·상담 상태·기존 보조 필터는 AND 조건으로 교차 적용한다.

## 화면 구조

내보내기 폼의 첫 줄은 `내보내기 대상`과 `담당 교수`로 구성한다. 이름·학교 검색은 기본 흐름에서 제거하지 않되 `추가 검색` 영역으로 낮춘다. 학년·지역·관심 분야·상담 상태·참여 기간은 보조 필터로 유지한다. 필터를 초기화하면 새 두 필터도 함께 비운다.

## 데이터 계약과 안전성

새 필터는 TypeScript Zod 스키마와 PostgreSQL의 `filter_snapshot` 검증을 모두 통과해야 한다. 기존 job의 스냅샷에는 새 필드가 없으므로 이전 job과 호환된다. 행 수 집계와 학생·참여·상담 세 시트의 행 조회는 같은 matcher를 사용해 일관되게 필터링한다.

XLSX의 `학생목록`에는 `내보내기 분류` 열을 추가한다. 이 값은 필터가 없을 때도 각 학생의 현재 운영 분류를 표시한다. 상담현황의 실제 배정 교수 열은 유지한다.

## 비범위

- 새 테이블, 별도 집계 작업, 외부 API는 추가하지 않는다.
- 학생 원본 정보와 상담 이력은 수정하지 않는다.
- 추천 교수 기준으로 내보내지 않는다.
